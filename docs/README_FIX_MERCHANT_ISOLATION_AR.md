# إصلاح ربط حساب التاجر — سوقنا

## ما الذي تغيّر في الكود؟
- أُلغي الاعتماد على `shops[0]`؛ حساب التاجر لا يفترض أن أول متجر في قاعدة البيانات يخصه.
- لوحة التاجر تبحث عن متجر مربوط بمعرّف حسابه `owner_id`.
- طلبات لوحة التاجر لم تعد تدمج طلبات العميل المحفوظة محليًا مع طلبات المتجر.
- تحديث حالة الطلب يقيّد الطلب بمعرّف المتجر الحالي.
- تسجيل حساب تاجر جديد يضيف `account_type: merchant` إلى بيانات الحساب.

## خطوة قاعدة البيانات المطلوبة قبل اختبار إدارة المحل
1. افتح Supabase ثم SQL Editor.
2. افتح الملف `SETUP_MERCHANT_OWNERSHIP_AR.sql` وانسخ أوامره غير المعلّقة وشغّلها.
3. من Authentication > Users انسخ UUID لحساب التاجر الصحيح.
4. حدّد المتجر الصحيح ثم عيّن `owner_id` لذلك المتجر باستخدام أمر UPDATE المعلّق في الملف بعد استبدال القيم.
5. راجع نتائج استعلام `pg_policies` الموجود بالملف. يجب ضبط سياسات RLS على `shops` و`products` و`orders` بحيث تمنع التاجر من قراءة/تعديل بيانات متجر آخر. إضافة سياسة جديدة وحدها لا تكفي إذا كانت هناك سياسات permissive قديمة تسمح للجميع.

**تنبيه:** هذا تحديث للكود وتجهيز قاعدة البيانات، وليس تأكيدًا أن العزل أصبح آمنًا بمجرد تثبيت APK. لا تنشر النسخة على أنها آمنة للتجار قبل إكمال ربط `owner_id` ومراجعة سياسات RLS واختبار حسابين مختلفين.
